Idempotent consumers trade storage for safe retries

Statement

Making message consumers idempotent allows at-least-once delivery and retries without duplicate side effects, at the cost of deduplication state, retention policy, and coordination.

Invariant

For a given idempotency key, applying the same operation more than once produces the same externally visible result as applying it once.

Record effect atomically enoughOn first application the consumer persists the result or marks the key seen so subsequent retries take the no-op/return-prior-result path.seen-check
Safety gained, state and lifecycle addedRetries become safe under redelivery and crashes, but the system must store, expire, and sometimes distribute dedupe state, and define behavior when keys collide or state is lost.record, seen-check

Complexity

O(1) average deduplication check/record per message plus storage proportional to retained keys; enables correctness under at-least-once delivery.
